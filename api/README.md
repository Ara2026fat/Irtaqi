# ارتقِ — الخدمةُ الخلفيّة (Cloudflare Workers + D1)

بنيةٌ **جاهزةٌ غيرُ منشورة**. الكودُ مُختبَرٌ محلّيًّا، ونشرُه أمرٌ واحدٌ حين يَصل النطاق.

| الملفّ | ما فيه |
|---|---|
| `wrangler.jsonc` (في الجذر) | إعدادُ العاملِ `irtaqi`: المهمّةُ المجدوَلةُ وربطُ D1 |
| `api/worker.js` | الخدمةُ كلُّها: `fetch` و`scheduled` |
| `api/schema.sql` | الجداولُ والفهارس |
| `api/test.mjs` | اختبارٌ محلّيٌّ بلا حسابٍ ولا شبكة: `node api/test.mjs` |

**المبدأُ الأوّل:** الخادمُ لا يَعرف القارئ. لا اسمَ ولا بريدَ ولا جوالَ ولا محتوى حفظٍ مقروءًا.
و`blob` نصٌّ مُعمًّى من طرفٍ إلى طرف (AES-GCM): يُخزَّن كما هو، ولا يُحلَّل، ولا يَقدر الخادمُ على فكِّه.

## ١) النشرُ — خطوةً خطوة

كلُّ الأوامرِ من **جذرِ المستودع** لا من مجلّدِ `api`.

```bash
# ١. الدخولُ إلى حسابِ Cloudflare (يَفتح المتصفّحَ مرّةً واحدة)
npx wrangler login

# ٢. إنشاءُ قاعدةِ البيانات — يَطبع الأمرُ database_id
npx wrangler d1 create irtaqi-db
```

> انسخ `database_id` المطبوعَ وضَعه في `wrangler.jsonc` مكانَ `"database_id": ""`.
> بغيرِه يَفشل النشرُ برسالةٍ صريحة.

```bash
# ٣. إنشاءُ الجداولِ في القاعدةِ البعيدة
npx wrangler d1 execute irtaqi-db --remote --file=api/schema.sql

# ٤. مفتاحُ الأرقامِ (لك وحدَك). لاتينيٌّ لا عربيٌّ — انظر التحذيرَ أدناه
npx wrangler d1 execute irtaqi-db --remote \
  --command "INSERT OR REPLACE INTO cfg(k,v) VALUES('STATS_KEY','PUT-A-LONG-RANDOM-LATIN-SECRET-HERE')"

# ٥. النشر
npx wrangler deploy

# ٦. مفتاحُ VAPID العامّ (يولّده العاملُ بنفسِه عند أوّلِ طلبٍ ويَحفظه في cfg)
curl https://irtaqi.<حسابك>.workers.dev/api/push/key
```

> ⚠️ **قيمُ ترويساتِ HTTP لاتينيّةٌ (ISO-8859-1).** فمفتاحُ `STATS_KEY` ومفتاحُ الجهازِ
> `x-irtaqi-key` لا يَصلح فيهما حرفٌ عربيٌّ: المتصفّحُ يَرفض الترويسةَ من أصلِها.
> (عرَفناه من الاختبارِ: سقطَ أوّلُ تشغيلٍ بهذا السبب بالضبط.)

### الأرقام
```bash
curl -H "x-stats-key: <STATS_KEY>" https://irtaqi.<حسابك>.workers.dev/api/stats
```
مجاميعُ لا صفوفٌ: المثبَّتون، والنشِطون (اليومَ/٧/٣٠)، وعددُ مَن فعّل التذكير، وحجمُ المُزامَن.
والدولةُ التي فيها أقلُّ من **خمسةِ** أجهزةٍ تُجمع في «أخرى» كي لا يَدلَّ رقمٌ على شخصٍ بعينِه.

### حين يَصل النطاق
بعد إضافةِ `irtaqi.app` إلى Cloudflare، أضِف في `wrangler.jsonc`:

```jsonc
"routes": [ { "pattern": "irtaqi.app/api/*", "zone_name": "irtaqi.app" } ]
```

ثمَّ `npx wrangler deploy`. فيُصبح الموقعُ والخدمةُ على **أصلٍ واحد**: لا CORS، ولا عنوانٌ
ثانٍ في العميل، وعاملُ الخدمةِ يَرى الكلَّ من نطاقِه. والموقعُ يَبقى على GitHub Pages كما هو:
المسارُ `/api/*` وحدَه يَذهب إلى العامل.

**وإن أردتَ لاحقًا أن يَخدم هذا العاملُ الموقعَ أيضًا** (بدلًا من Pages) فأضِف `assets` —
ولكن **أنشئ `.assetsignore` أوّلًا** واستثنِ فيه `CONTRACT.md` و`deploy.py` و`api/**` و`.git`،
فجذرُ المستودعِ يَحمل ملفّاتٍ خاصّةً لا تُنشر للناس. هذا هو السببُ الذي لأجلِه لم أضَعْ
`assets` في الإعدادِ من البداية.

## ٢) ما يَنقص في العميل (ثلاثةُ أشياءَ صغيرة)

### أ) مفتاحُ الجهازِ — يَسُدُّ أخطرَ ثغرةٍ في العقد
في العقدِ كما هو، **المعرّفُ وحدَه كلمةُ السرّ**: مَن عرَفَ `id` قَرأ النسخةَ المُعمّاةَ (لا يَفكّها،
لكنَّه يَأخذها)، و**دَفعَ فوقَها فأتلفَ حفظَ صاحبِها**. وهو يَمرُّ في مسارِ العنوانِ (`?id=`) فيَقع
في السجلّاتِ والـReferrer.

الخدمةُ تَقبل — بلا نقضٍ للعقدِ — ترويسةً اختياريّة:

```js
// سرٌّ عشوائيٌّ يولَد على الجهازِ مرّةً، لا يُشتقُّ من مفتاحِ التعميةِ ولا يُرسَل معه
headers: { 'x-irtaqi-key': deviceKey }   // لاتينيٌّ، ١٦–٢٠٠ محرفًا
```

أوّلُ كتابةٍ تَختم الصفَّ ببصمةِ المفتاح (SHA-256؛ المفتاحُ نفسُه لا يُخزَّن)، وبعدَها
يُرَدُّ كلُّ طلبٍ بلا مفتاحٍ صحيحٍ بـ401. ومَن لم يُرسلها عمِلَ كما كان، فلا ينكسرُ شيء.

> **نُفِّذ في العميلِ بالفعل** — `src/19-cloud.js`، الدالّةُ `sign()`: سرٌّ عشوائيٌّ من ٣٢ بايتًا
> (Base64) يُولَد مرّةً ويُحفَظ في `localStorage` خارجَ حالةِ التطبيق، ويُرسَل في **كلِّ** طلب.
> فلا صفَّ يُكتَب بلا قفلٍ منذ أوّلِ يوم.

وللمزامنةِ قفلٌ آخرُ فوقَه: عنوانُها (`id`) ومفتاحُها يُشتقّان من **كلمةِ مزامنةٍ** يَملكها
القارئُ (`App.Seal.ident`)، لا من معرّفِ الجهاز. وبه يَبلغ صاحبُ الكلمةِ نسختَه من أيِّ جهازٍ
ولو ضاع الأوّل — ولا تَبلغها أنت ولا الخادم.

### ب) مفتاحُ VAPID العامّ
`pushManager.subscribe` يَطلب `applicationServerKey`، وليس في عقدِك نقطةٌ تُعطيه. فزِدتُ
`GET /api/push/key → {ok:true,key}` (زيادةٌ لا تَنقض شيئًا). إمّا تَقرؤه من هناك مرّةً وتُثبّته
في العميل (فهو عامٌّ لا سرَّ فيه)، وإمّا تَسحبه عند أوّلِ تشغيل.

### ج) نصُّ الإشعارِ عندَك لا عندي
الخادمُ يُرسل إشعارًا **بلا حمولة**: يَقرع البابَ فقط. وهذا مقصودٌ — فلا نَحتاج مفاتيحَ
الاشتراكِ (`p256dh`/`auth`)، ولا يَمرُّ حرفٌ من حالِ القارئِ على خادمِ الدفع. فاكتُب النصَّ في
`sw.js` عندَك:

```js
self.addEventListener('push', (e) => {
  e.waitUntil(self.registration.showNotification('ارتقِ — وِردُك', {
    body: 'صفحتُك تنتظرك. ابدأ بآيةٍ واحدة.',
    icon: '/icon-192.png', tag: 'irtaqi-wird', dir: 'rtl', lang: 'ar'
  }));
});
```

نصٌّ لا يَلوم مَن تأخّر: لا «فوّتَ» ولا «انقطعتَ» ولا عدَّ أيّامٍ ضائعة.

## ٣) كم مستعمِلًا تَحتمل الطبقةُ المجّانيّة؟

**الحدودُ المُعلَنة** (Cloudflare، نوفمبر ٢٠٢٦): طلباتُ العاملِ ١٠٠٬٠٠٠/يوم، ومعالجةٌ ١٠ م.ث
لكلِّ استدعاء، و٥٠ طلبًا خارجيًّا و٥٠ استعلامَ D1 لكلِّ استدعاء؛ وD1: قراءةُ ٥٬٠٠٠٬٠٠٠ صفٍّ/يوم،
و**كتابةُ ١٠٠٬٠٠٠ صفٍّ/يوم**، وتخزينُ ٥٠٠ م.ب للقاعدةِ الواحدة. وحجمُ السلسلةِ أو الصفِّ ٢٬٠٠٠٬٠٠٠ بايت.

**التكلفةُ المقيسةُ** (من `node api/test.mjs`، وهي صفوفُ الجداولِ كما عدَّتها SQLite، ويُزاد عليها
صفُّ فهرسٍ حيث يُحدَّث عمودٌ مُفهرس):

| الطلب | كتابة | قراءة |
|---|---|---|
| `POST /api/ping` أوّلَ مرّةٍ في اليوم | ٢ (صفٌّ + فهرسُ `last_day`) | ٢ |
| `POST /api/ping` مُعادًا في اليومِ نفسِه | **٠** | ١ |
| `GET /api/sync` | **٠** | ١ |
| `POST /api/sync` | ١ | ٢ |
| `POST /api/push/sub` (نادر) | ٢ | ٢ |
| إيقاظٌ في المهمّةِ المجدوَلة | ٢ | ~٢ |

**مستعمِلٌ نشِطٌ في يومٍ عاديّ** (يَفتح التطبيقَ مرّتَين، ويُزامن مرّتَين، وعندَه تذكيرُ وِرد):
٦ طلباتٍ، و**٦ صفوفٍ مكتوبة**، و~١١ صفًّا مقروءًا.

| الحدُّ | الحساب | السعة |
|---|---|---|
| طلباتُ العامل | (١٠٠٬٠٠٠ − ١٬٤٤٠ للمهمّةِ المجدوَلة) ÷ ٦ | **≈ ١٦٬٤٢٦ مستعمِلًا نشِطًا/يوم** |
| كتاباتُ D1 | ١٠٠٬٠٠٠ ÷ ٦ | **≈ ١٦٬٦٦٦** |
| قراءاتُ D1 | ٥٬٠٠٠٬٠٠٠ ÷ ١١ | ≈ ٤٥٤٬٠٠٠ (لا يَربط) |
| التخزين | ٥٠٠ م.ب ÷ معدّلِ حجمِ الـblob | ٢٥٬٠٠٠ عند ٢٠ ك.ب — و**٥٬٠٠٠ عند ١٠٠ ك.ب** |

### الجوابُ: **≈ ١٦٬٠٠٠ مستعمِلٍ نشِطٍ يوميًّا**
يَربطها حدّانِ معًا (الطلباتُ والكتابات) عند الرقمِ نفسِه تقريبًا — وهذا ليس مصادفةً بل
نتيجةُ تصميم: `GET /api/sync` و`ping` المُعادُ لا يَكتبان شيئًا.

**وشرطُه** أن يَبقى معدّلُ حجمِ الـblob حولَ ٢٠ ك.ب. فإن كبُرَ إلى ١٠٠ ك.ب صارَ **التخزينُ**
هو الرابطَ عند ~٥٬٠٠٠ مستعمِل، قبلَ أن تَصل إلى حدِّ الطلباتِ بثُلثِ الطريق. راقِبْ
`syncedBytes` في `/api/stats`: هو العدّادُ الذي يُنذرك.

### سقفٌ آخرُ لا يَظهر في الفواتير: ٤٠ إشعارًا في الدقيقة
الطبقةُ المجّانيّةُ تُجيز ٥٠ طلبًا خارجيًّا لكلِّ استدعاء، فالمهمّةُ المجدوَلةُ تُرسل ٤٠ وتُبقي فضلة.
والبقيّةُ تَبقى مستحقّةً فتَأخذها الدقيقةُ التالية — بسقفِ تأخّرٍ ٤٥ دقيقة، فما بعدَها يُؤجَّل
ليومِه (كي لا يُوقَظ أحدٌ في الثالثةِ فجرًا). ومعناه: **١٬٨٠٠ مشترِكٍ** كحدٍّ أقصى على
**الدقيقةِ الواحدةِ في المنطقةِ الواحدة**. ولأنَّ الناسَ يَختارون الساعاتَ المستديرة (٢٠:٠٠،
٢١:٠٠) أرشّح أن يَبثَّ العميلُ الدقيقةَ قليلًا: اقترِح على القارئِ دقيقةً غيرَ الصفرِ
(٢٠:٠٧ مثلًا) أو أضِف إزاحةً ثابتةً مشتقّةً من معرّفِه. وبالترقيةِ المدفوعةِ يَرتفع السقفُ
إلى ألوفٍ في الدقيقة بتغييرِ `PUSH_PER_TICK` وحدَه.

### ملاحظاتٌ على الحساب
- **١٬٤٤٠ استدعاءً للمهمّةِ المجدوَلةِ في اليوم** حُسبت على أنّها تُعَدُّ من حدِّ الطلبات
  (تقديرٌ متحفّظ؛ وثائقُ Cloudflare لا تَنصُّ عليه صراحةً) — وهي ١٫٤٪ منه فلا تُغيّر النتيجة.
  وفي الدقيقةِ التي لا وِردَ فيها تَقرأ **صفرَ صفوفٍ** وتَكتب **صفرًا**، بفضلِ فهرسِ `next_at`.
- الحدُّ الحقيقيُّ هو **عددُ نداءاتِ العميلِ في اليوم**. كلُّ `POST /api/sync` زائدٍ يُنقص السعةَ
  ~٢٬٧٠٠ مستعمِل. فلا تُزامن عند كلِّ آيةٍ تُحفظ: اجمعْ التغييراتَ ودَعِ المزامنةَ تَنطلق
  عند الإغلاقِ أو بعد سكونٍ (debounce) ثلاثينَ ثانية.
- حدُّ المهامِّ المجدوَلةِ في الحسابِ المجّانيِّ **خمسٌ**، وزاحِمُ يَستهلك واحدة. فهذه الثانية.
- ترقيةُ Workers Paid ($٥/شهر) تَرفع الطلباتَ إلى عشرةِ ملايينَ شهريًّا والكتاباتِ إلى
  ٥٠ مليونًا، فتَصير السعةُ بمئاتِ الألوف — ويُصبح التخزينُ (١٠ ج.ب) هو الرابطَ لا العدّادات.

## ٤) الاختبار

```bash
node api/test.mjs      # ٥٣ اختبارًا، بلا حسابٍ ولا شبكةٍ ولا wrangler
```

يُشغّل `fetch` و`scheduled` مباشرةً على `node:sqlite` خلفَ طبقةٍ تُحاكي D1، ويُغطّي:
المسارَ السعيدَ لكلِّ نقطة، والمعرّفَ الفاسدَ، وblob المجاوزَ، و409 عند تضاربِ `rev`،
واختيارَ مَن يُوقَظ في أربعِ مناطقَ زمنيّة، والتوقيتَ الصيفيَّ (قفزةَ الربيعِ وعودةَ الخريف)،
وصفًّا فاسدًا في الجدولِ لا يُسقِط الدقيقةَ عن الباقين، ومفتاحَ الجهازِ، وحدَّ المعدّل،
وتكلفةَ الصفوفِ لكلِّ طلب.

وعلى بيئةِ التشغيلِ الحقيقيّة:

```bash
npx wrangler d1 execute irtaqi-db --local --file=api/schema.sql
npx wrangler dev --local
curl http://localhost:8787/cdn-cgi/handler/scheduled     # يُشغّل scheduled() مرّةً
```

## ٥) الخصوصيّة — ما يُخزَّن وما لا يُخزَّن

**يُخزَّن:** معرّفٌ عشوائيٌّ يولّده الجهاز؛ تاريخُ أوّلِ وآخرِ استعمالٍ (باليومِ لا بالساعة)؛
نسخةُ التطبيق؛ رمزُ الدولةِ من ترويسةِ Cloudflare؛ النصُّ المُعمّى كما هو؛ وللمشترِكِ في
التذكير: عنوانُ خدمةِ الدفعِ وساعةُ وِردِه ومنطقتُه الزمنيّة.

**لا يُخزَّن:** اسمٌ، بريدٌ، جوالٌ، موقعٌ دقيق، عنوانٌ شبكيٌّ (IP يُستعمل في الذاكرةِ لحدِّ
المعدّلِ ولا يُكتب أبدًا)، مفاتيحُ اشتراكِ الدفعِ (`p256dh`/`auth` — لا حاجةَ لها فلا نَأخذها)،
ولا مفتاحُ الجهازِ نفسُه (بصمتُه فقط)، ولا أيُّ شيءٍ عمّا يَحفظه القارئُ أو كم حفِظ.

**ثغراتٌ رأيتُها في العقدِ — فيها ما يَحتاج قرارَك:**

1. **المعرّفُ وحدَه كلمةُ السرّ** (الأخطر). الحلُّ جاهزٌ في ٢-أ أعلاه، وينتظر سطرًا في العميل.
2. **`id` في مسارِ العنوان** (`GET /api/sync?id=…`). يَقع في سجلّاتِ الخادمِ والوسائطِ. وهو
   معرّفٌ مجهولٌ لا اسمٌ، فالضررُ محدود؛ ومع مفتاحِ الجهازِ لا يَنفع مَن سرَقه. تركتُه كما
   هو احترامًا للعقد، وأرشّح في النسخةِ القادمةِ نقلَه إلى ترويسة.
3. **`tz` بصمةٌ خفيفة.** «Asia/Riyadh» لا تَدلُّ على أحد، لكنَّ منطقةً نادرةً
   (`America/Indiana/Vincennes`) + ساعةَ وِردٍ + وقتَ طلبٍ تَضيق على عدد. فلذلك لا تُظهِر
   `/api/stats` أيَّ توزيعٍ للمناطقِ الزمنيّةِ أصلًا، ولا يُسجَّل شيءٌ منها في السجلّات.
4. **عنوانُ خدمةِ الدفعِ مُعرِّفٌ بطبيعتِه** (يُصدره Google/Apple/Mozilla للجهاز). لا مَهربَ
   منه في إشعاراتِ الويب، وهو يُحذَف لحظةَ `unsub` أو عند أوّلِ ٤٠٤/٤١٠.
5. **سقفُ ٢ م.ب في عقدِك لا يُمكن تنفيذُه كما هو:** حدُّ D1 للصفِّ ٢٬٠٠٠٬٠٠٠ بايتًا **بما فيه
   المعرّفُ والعدّادُ والبصمة**، فـ٢ م.ب (٢٬٠٩٧٬١٥٢) يَرفضها D1 نفسُه. فالسقفُ المنفَّذ
   **١٬٥٠٠٬٠٠٠ بايتًا** (مقيسةً بالبايتِ لا بالمحرف — فالعربيُّ بايتانِ للحرف)، وما جاوزَ يُرَدُّ بـ413.
   وجرّبتُ ١٬٤٩٩٬٠٠٠ بايتًا على D1 حقيقيّةٍ فخُزّنت.

**التنظيفُ** (اختياريٌّ، مرّةً في السنة):
```bash
# صفوفٌ لم تُمَسَّ سنةً: لمن مسحَ التطبيقَ ولن يعود
npx wrangler d1 execute irtaqi-db --remote \
  --command "DELETE FROM blobs WHERE updated < strftime('%s','now','-365 day')*1000"
npx wrangler d1 execute irtaqi-db --remote \
  --command "DELETE FROM ctr WHERE d < date('now','-30 day')"
```

## ٦) حدودُ الحمايةِ المضبوطةُ في `worker.js`

| الثابت | القيمة | لماذا |
|---|---|---|
| `MAX_BLOB` | ١٬٥٠٠٬٠٠٠ بايت | دونَ حدِّ صفِّ D1 بمسافةٍ آمنة |
| `MAX_BODY` | ٢٬٢٠٠٬٠٠٠ | يُرَدُّ الجسمُ الضخمُ من ترويسةِ `content-length` قبل قراءتِه |
| `PUSH_PER_TICK` | ٤٠ | حدُّ الطلباتِ الخارجيّةِ ٥٠ لكلِّ استدعاء |
| `LATE_MS` | ٤٥ دقيقة | ما تأخّرَ أكثرَ لا يُوقِظ أحدًا في غيرِ حينِه |
| `NEW_IDS_PER_DAY` | ٣٬٠٠٠ | سدٌّ في وجهِ مَن يَملأ القاعدةَ بمعرّفاتٍ مُختلَقة |
| `RL.sync` / `RL.sub` / `RL.ip` | ٣٠ / ١٠ / ١٥٠ في الدقيقة | حدُّ معدّلٍ بلا كتابةٍ واحدةٍ في D1 |

حدُّ المعدّلِ عدّادٌ في ذاكرةِ العزلة: ليس حاجزًا تامًّا (لكلِّ مركزِ بياناتٍ عزلتُه)، لكنَّه
يَكسر الموجةَ مجّانًا. والسدُّ الحقيقيُّ أمامَ التضخّمِ هو `NEW_IDS_PER_DAY` — كتابةٌ واحدةٌ
لكلِّ معرّفٍ جديدٍ لا لكلِّ طلب. وإن احتجتَ حاجزًا صارمًا فلـCloudflare ربطُ
Rate Limiting أصليٌّ مجّانيٌّ لا يَمسُّ D1؛ أُضيفه متى شئت.
